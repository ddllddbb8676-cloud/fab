## 3. 사용자의 작업 방식과 반드시 지킬 선

- 직접 협업하고 결과부터 간결하게 보고한다. 고정 팀장·직원 조직이나 불필요한 업무표를 만들지 않는다. 이미 승인된 필요한 작업을 반복 승인 질문으로 중단하지 않는다.
- 최우선은 **게임 이용에 지장을 주지 않는 것**이다. 분석·관리자·렌더링 기능 때문에 입장이나 움직임이 멈추면 안 된다.
- 기존 사용자 ID, 닉네임, 칩, 보유·장착 아이템, 파괴·수리 기록, Google 연결을 보존한다. 새로고침·배포를 초기화로 구현하지 않는다.
- 사용자가 관리 화면에서 말하는 “아이디”는 **팹뿌 닉네임**이다. Google 이메일·subject·쿠키·토큰·내부 식별자는 노출하지 않는다.
- 작은 HUD, 짧은 문구, 넓게 보이는 게임 화면을 선호한다. 큰 상시 패널, 거대한 여백, 영구 방향 화살표 등은 요청 없이 늘리지 않는다.
- 현재 느낌이 마음에 들면 유지한다. 특히 카메라 자동 회전은 멀미 때문에 명시적으로 원복한 사항이다.
- 예약 작업은 기본 중지다. 사용자의 명시적인 시작·재개 요청 없이 새 heartbeat나 자동 점검을 만들지 않는다. 과거 `fab-2`는 완료 후 삭제된 작업이며 되살리지 않는다.
- 예전 “실제 접속 2명 이하일 때만 판매 집계/관리자 배포” 조건은 이후 사용자가 “계속 확인하지 말고 일단 진행”으로 해제했다. 오래된 가드만 읽고 무한 대기하지 않는다. 그래도 진행 중 게임 이벤트와 데이터 보호는 고려한다.
- 대화방 제목은 최신 사용자 지시의 `🟡/🟢/🔴 + 프로젝트 이모지 + 짧은 업무명 · M/D HH시`를 따른다. 시각은 마지막 사용자 메시지의 KST. 완료는 반드시 🟢, 단순 미실행을 🔴로 표시하지 않는다.

## 4. 게임 기본 구조와 보존할 조작

팹은 약 120×180m, 층고 5m, 18개 베이 × 20대 = 360대 장비의 게임 공간이다. 두 줄의 장비 전면 통로·후면 서비스 통로, 로드포트, 상부 OHT 선로와 교차로, 입장 에어샤워, 공정별 조명을 구현했다. 사용자는 규모를 임의로 줄이길 원하지 않는다. 실제 팹 설계·생산량을 인증한 모델은 아니다.

- 장비 이름은 공정·팹·베이·순번을 반영한다. 설비 배치와 로드포트·OHT 좌표가 함께 맞아야 한다. [배치 근거](layout-references.md), [장비 이름](equipment-names.md), [용량 검토](capacity-plan.html).
- 빨간 EMO 부근을 누르면 캐릭터가 걸어가 손으로 누르고 장비가 붕괴한다. 파손 장비를 선택해 걸어가 수리한다. 수리 찾기는 가까운 순서이며 불필요한 모바일 키보드 검색창을 없앴다.
- 파괴음은 처음 큰 충격 이후 금속·파편 소리가 이어지는 느낌이다. 효과음 재생 시 공조음을 낮춘다. 효과음/공조음 각각 켜고 끈다.
- FOUP 들기·놓기·던지기·청소, OHT 점프 탑승·하차, 앉기·눕기, 감정표현, 짧은 대화, 카트 이동이 있다.
- 기본 조작은 **왼쪽 가상 조이스틱 이동 + 화면 드래그 시점 회전**의 3인칭 방식이다. 바닥을 눌러 걸어가는 기능도 기존 구현에 맞춰 유지한다.
- OHT는 온전한 장비를 밟고 뛰어 매달려 순회한다. 기존 화물은 바닥으로 내려온다. 실제 탑승 시간으로 보상하며 보기만 한 시간을 보상하지 않는다.
- 전체 보기의 바닥 줄무늬/얼룩은 깊이 정밀도와 겹친 상면 문제를 수정했다. 카메라 near/far를 시점별로 관리하고 일반 시점은 원래 값을 복구한다. [바닥 수정](overview-floor-fix-2026-11-02.md).
- **정원 표기 100에는 NPC 34명이 포함된다.** 기본 방문자 슬롯 66. 역할은 FOUP 5 / OHT 5 / 휴식 5 / 수리 2 / 파괴 13 / 안전팀 4. 운영자 특별 입장 규칙은 별도 코드 확인. HUD의 “함께 40명”을 실제 이용자 40명으로 분석하면 안 된다.
- 계정 프로필과 파손 장비·FOUP 상태를 저장한다. 명시적인 “완전히 새로 시작하기” 같은 사용자 선택 외에는 기록을 지우지 않는다.

## 5. 연결 안정화와 카메라 변경 이력

### 접속 문제

11/3 iPhone Instagram 내부 브라우저에서 HTML·기본 WebGL 점검은 정상이지만 게임이 “팹 연결 중”, 임시 닉네임, 기록 대기로 오래 남는 제보가 있었다. HTTP 진입, 쿠키 준비, 파일 캐시, 실시간 연결, 재접속 경쟁을 각각 수정했다. **아이템 색상이나 누적 계정 수가 모든 지연의 원인이었다고 확정한 적은 없다.** 일반 입장은 해당 프로필을 읽으며 전체 프로필 스캔은 방 기동 등의 별도 경로다.

- 게임/API HTTP 진입은 같은 HTTPS로 308 전환한다. 전환 중 새 계정 쿠키를 발급하지 않는다.
- 설정·쿠키 준비, 모듈 다운로드, WebSocket 사전 연결을 병행하고 같은 연결을 게임에 인계한다. 입장 응답이 오기 전 임시 정보를 실제 기록으로 오인시키지 않는다.
- 무응답·오래된 연결을 종료하고 재시도하며 늦게 온 이전 연결 응답을 무시한다. WebSocket이 불안정한 환경은 HTTP 대체 연결을 지원한다.
- 파일 해시는 시작 JS 하나가 아니라 상대 import와 worker를 포함한 **전체 모듈 그래프**에 일관되게 붙인다. 이전 코드와 새 코드가 섞이는 캐시 회귀를 막는다.
- [연결 안정화](connection-stability-2026-11-03.md), [캐시 수정](connection-cache-fix-2026-11-03.md), [새로고침 전송](refresh-transport-2026-11-03.md), [수리 탐색 최적화](repair-directory-fix-2026-11-02.md).

회사 PC의 “안정성 미확인 사이트를 가상환경으로 접속” 환경에서는 계속 느렸고 사용자가 포기했다. **회사 보안 우회는 요청하지 않았으며 계속 추진할 과제가 아니다.** [사내 PC 기록](company-pc-entry-2026-11-04.md).

### 카메라 최종 결정

장비 사이·스토커 앞에서 카메라가 너무 붙는 문제로 거리·각도·전환 실험을 했지만, 사용자가 자동 회전과 탑뷰 전환 때문에 멀미를 느껴 **손대기 전 조작으로 원복**했다. 당시 기준은 `b1bd6fd:src/explorer.js`다. 현재 파일 전체를 옛 커밋으로 무조건 덮지 말고 이후 별도 개선을 보존한다.

- 벽·스토커·이모지 사용 때문에 카메라를 자동으로 크게 돌리는 기능을 다시 넣지 않는다.
- 스토커 OUT 클릭 범위를 글자 쪽까지 넓힌 개선은 유지한다. IN과 겹치지 않는다.
- 명시적인 이벤트 성공 연출의 잠깐 탑뷰와 원래 시점 복귀는 별도 기능이다.
- [카메라 원복](camera-rollback-2026-11-04.md)이 [통로 실험](passage-camera-2026-11-04.md)과 [전환 실험](camera-transitions-2026-11-04.md)보다 우선한다.
- OHT 시점 끊김은 실제 경과 시간 기반 보간으로 수정했다. HTTP/WS 간격 차이를 반영하고 오래된 상태는 따라잡으며 알려진 경로 밖으로 무리하게 예측하지 않는다. [상점/OHT 수정](shop-oht-2026-11-05.md).

1. 👋 😆 ❤️ 😭 😱 👻 👍 😡 😎 — 사용자가 지정한 첫 줄.
2. 😁 🥳 👏 🙏 🥺 😅 😳 😔 😑

## 8. 안전팀·파손 재고·FOUP 장난과 청소

### 안전팀과 수리할 장비

- 실제 유저 안전팀은 누적 플레이 5분부터 자격, 임무 종료 후 플레이 10분 대기, 다른 사람에게 넘길 때 15초, 동시 1명, 서로 다른 대상 3명 포획이다. 오프라인 시간이 플레이 대기로 쌓이지 않는다. 이전 저장의 버전 이관은 한 번만 한다.
- **NPC 안전팀만 속도 20% 감소: 2.1→1.68m/s.** 실제 이용자/유저 안전팀 속도 3.2m/s는 유지한다.
- 잡힐 때 약 1.15초 놀라 손을 드는 “들켰다!” 동작을 넣었다. 기본 패널티는 장비 3대 수리. 쿠폰이 있으면 보유 수를 보여주고 1장으로 즉시 해제, 재포획 유예 12초를 둔다.
- 수리할 파손 장비는 NPC 기준 **50대 보존 / 60대 확보 목표**다. 13명의 파괴 NPC가 파손이 적은 베이부터 걸어가 실제로 부순다. NPC 수리는 예약까지 계산해 50대를 남긴다.
- 사용자의 수리는 제한하지 않는다. 여럿이 빠르게 수리하면 일시적으로 50대 미만이 될 수 있으며 순간 강제 파손으로 숫자를 맞추지 않는다. 방금 수리한 장비는 NPC 파괴 45초 보호. 이벤트 대상·작업 중 장비 보호가 우선한다.

### FOUP 피격 장난

처음 안전팀을 골탕 먹이는 아이디어에서 시작해 최종적으로 **일반 사람과 NPC도 걷거나 가만히 있을 때만** 맞을 수 있게 확장했다. FOUP이 날아가는 경로의 몸에 맞거나 실제 파손 지점 가까이에 있으면 😡와 2초 헤롱 효과. 10초간 재기절 방지, 자기 FOUP·벽 너머·보호 구역 제외. 체력 피해나 계정 기록 차감 기능이 아니다.

수리·작업 접근·청소·카트 조작·탑승·앉기·눕기·잡힘/잡기 등 다른 행동 중에는 보호한다. 기존 경로·들고 있던 FOUP을 보존하고 회복 후 이어간다. 카메라를 자동 회전시키지 않는다. 기존 FOUP NPC가 조건이 맞을 때 안전팀 NPC에게 드물게 시범을 보이며 팹 전체 최소 90초 간격, 이벤트 중 시범 없음, 새 FOUP 생성 없음.

일반 던지기는 바닥에서 깨지고 웨이퍼·파편이 흩어진다. 단순 내려놓기나 하차 화물은 파손시키지 않는다. 사람은 잔해를 눌러 걸어가 3.2초 빗자루 청소 후 2칩을 얻는다. 중단·동시 청소·재전송은 중복 보상하지 않는다. 완료 후 약 12초 뒤 같은 화물 슬롯을 재사용해 빈 로드포트로 돌아간다.

## 10. 카트·무빙워크와 반복 수정한 문제

**카트는 두 대, 최종 조작은 끌기다.** 한때 밀기로 바꿨으나 사용자가 운전감이 부자연스럽다고 해 다시 끌기로 돌아왔다. 요청 없이 다시 밀기로 바꾸지 않는다.

- 긴 2단 카트에 아래 2개·위 2개, FOUP 총 4개. 사람은 아래·위 각 1명, 최대 2명 탑승한다. 사람이 타는 층에 있던 FOUP은 바닥에 온전하게 내려놓고 삭제하지 않는다.
- 다른 사람이 손잡이를 잡고 있거나 조금 움직여도 일정 거리에서 탑승할 수 있다. 승객도 화면 드래그로 시야를 조절한다. 서버 위치 보간·동기화와 카트 충돌을 함께 다뤘다.
- 구석에 낀 채 못 움직임, 무빙워크에서 카트만 원점으로 튀는 현상, 탑승자와 이동할 때 끊김을 여러 차례 수정했다. 최종 11/9에는 회전이 막혀도 충돌 없는 평행 이동으로 탈출하고 벨트가 손잡이를 밀어도 과도하게 비틀어지지 않도록 했다.
- 홈에서 15m 넘게 떨어져 120초 방치된 카트는 기존 NPC 1명이 회수한다. 손잡이·승객·근처 5m 사람·황금 화물·흑백 이벤트 등은 보호하며 사람이 돌아오면 양보한다. 2초 간격, 한 번에 한 카트만 처리한다.

- **무빙워크:** 중앙 메인 통로의 일자 양방향 바닥 벨트, 손잡이 없음, 어느 쪽으로든 벗어날 수 있음, 화살표로 방향 표시, 이동 속도 2배, 카트 사용 가능.

## 12. Google 계정 연결과 앱 논의

**Google 연결은 11/6 운영 반영 후 사용자가 자기 계정 연결 성공을 확인했다.** 초기 “연동했는데 다른 브라우저에 캐릭터 없음” 문제도 수정했다. Google 동의 이메일을 받은 것만으로 게임 캐릭터 저장 성공이라고 판단하지 않는다.

사용자가 구분해 달라고 한 세 가지 메뉴 의미를 유지한다.

1. **현재 캐릭터를 Google로 연결:** 지금 닉네임·칩·아이템을 선택한 Google 계정에 연결한다.
2. **Google로 로그인:** 다른 브라우저/PC에서 이미 연결한 캐릭터를 불러온다.
3. **원래 캐릭터 인증/연결 바로잡기:** 잘못 연결한 새 캐릭터가 있으면 원래 캐릭터에서 발급한 인증으로 확인하고 연결을 바로잡는다. 두 캐릭터를 알아보기 쉽게 안내하고 검증 없이 덮지 않는다.

첫 진입에서는 Google 연결/로그인과 **Google 없이 바로 시작**을 모두 지원한다. Instagram 내부 브라우저는 Google 인증 제한 때문에 외부 Safari/Chrome 흐름이 필요할 수 있다. 주소 복사·코드 반복 입력을 주 흐름으로 강요하지 않도록 자동 브라우저 인계·진행을 구현했다. Google의 계정 선택·동의까지 무조건 무인 자동화할 수 있다고 약속하지 않는다.

- Google의 검증된 subject로 연결하고 이메일·닉네임 일치로 기존 계정을 탈취하지 못하게 한다. audience/issuer/만료/nonce, 쿠키·요청 출처를 검증한다.
- 원래 캐릭터 인증용 코드는 짧은 유효기간(5분)·일회용이며 비밀 인증값이다. 문서·로그·URL 공유 자료에 실값을 남기지 않는다.
- **최초 Google 연결 성공 1,000칩, 한 번만 지급.** 기존 연결 계정 처리도 구현했다. 연결 저장과 보상 확정 전에 성공 화면을 띄우지 않는다.
- 미연결 계정의 KST 하루 첫 입장에 데이터 보호 안내와 1,000칩 보상을 설명하고 **바로 연동하러 가기 / 다음에 하기** 버튼을 준다. 읽을 시간을 주고 강제 즉시 닫기·반복 팝업을 피한다.
- 관리자에 실제 연결 수와 **게임 닉네임** 목록(25명씩)을 표시한다. Google 이메일/ID를 표시하지 않는다.
- 기준: [Google 연결 상세](google-account-link.md), `TODO.json`, `server/account-*`, `server/google-*`, `account/google.js`. Cloud 설정·OAuth 비밀값을 새로 만들거나 바꾸는 것은 별도 작업이다.

**카카오는 보류. Android/iOS 출시도 아직 하지 않았다.** 사용자는 iOS 비용이 부담돼 Android부터 고려했고 테스트 요건·비용을 질문했다. 웹/앱이 같은 서버와 계정을 쓰길 원한다. 향후 실제 착수 시 스토어 정책·비용·테스트 요건은 공식 최신 자료로 다시 확인한다. 당시 답변을 현재 가격 보장으로 쓰지 않는다.

### 해외 접속 흔적

`outputs/country-report/summary.json`의 기간은 **10/27 12:57~11/3 12:57 KST**다. `/api/room`의 실제 edge 요청 중 WebSocket 업그레이드 HTTP 101을 기준으로 해외 15개 국가 코드에서 142건을 확인했다. 미국 43 / 일본 42 / 싱가포르 22 / 대만 12 / 홍콩 8 / 인도네시아 3 / 베트남 3 / 캐나다 2 / 뉴질랜드·필리핀·프랑스·네덜란드·브라질·독일·영국 각 1.

이는 **IP 국가의 연결 요청 흔적**이다. 142명, 국적, 거주지, 입장 완료·실제 플레이를 뜻하지 않는다. 재시도·VPN·프록시·봇·검증 클라이언트가 포함될 수 있고 계정별 중복 제거 자료가 아니다. IP·계정 식별자·인증값을 보고서에 저장하지 않았다.

### DB와 서버비

데이터는 Cloudflare Durable Objects의 영속 저장소에 있고 GitHub에 사용자 DB가 저장되는 구조가 아니다. 게임 기록·세계 상태와 별도 분석 저장을 구분한다. 이미지/광고 영상/스크린샷을 이용 기록 DB에 쌓지 않는다. 현재 DB 용량·한도 여유는 필요할 때 실제 사용량으로 재확인한다.

11/9 사용자의 $5 결제 질문에 대해 사용량 기반 계산을 했다. `outputs/billing-review-20261109/estimate.json`은 **11/1~11/9 약 8.45일 추세를 30일로 환산한, 확인 항목 약 $5.30 추정**이다. 기본 $5가 비용 상한은 아니다. 실제 청구서 권한은 403이었고 저장 용량·다른 서비스 비용은 포함하지 않았으며 계정 전체 지표의 혼입도 구분해야 한다. 청구서 확인/월 비용 보장으로 표현하지 않는다. 사용자는 작은 추가 비용은 괜찮다고 했지만 무제한 비용을 승인한 것은 아니다. 결제·예산 설정은 바꾸지 않았다.

## 17. 데이터·인증·배포 안전 수칙

### 보존할 것

- 기존 사용자 프로필, 지갑, 보유/장착, Google 연결, 닉네임 레지스트리, 장비·FOUP·이벤트 체크포인트를 보존한다. 코드 롤백과 DB 롤백은 다르다.
- `FAB_OWNER_VISITOR_ID`, 검증 제외 secret, 두 DO 바인딩과 이름, 마이그레이션을 무심코 바꾸지 않는다. 운영자 권한을 nickname 비교로 대체하지 않는다.
- 인증 쿠키·토큰·OAuth 비밀값·개별 사용자 원시 자료를 Git·채팅·공개 문서에 넣지 않는다. `outputs/verification-observer-cookie.txt` 등은 로컬 비공개 자료다. **이 파일을 출력하거나 커밋하지 않는다.**
- `outputs/`, `.wrangler/`, `node_modules/`, `.env*`, `.dev.vars*`, 로그는 Git 제외다. 증거를 넘기려고 `git add -f outputs` 하지 않는다. 필요한 비식별 요약만 문서에 쓴다.
- 테스트용 코드는 로컬 격리 Worker·합성 계정을 사용한다. 운영 계정을 새로 만들거나 실제 구매·보상·이벤트를 시험으로 실행하지 않는다. 기존 검증 계정도 상태 변경 없이 읽기 확인한다.

### 필요한 경우의 검증·배포 순서

1. 현재 Git 변경·원격·운영 버전 확인. 다른 사람 변경을 덮지 않고 작업 범위를 정한다.
2. 해당 기능 문서와 회귀 테스트를 읽는다. 변경에 맞는 검사를 한 번 제대로 실행하고, 실패·새 변경·미해결 위험이 없으면 같은 검사를 불필요하게 반복하지 않는다.
3. `npm run check`, 필요한 `node --test tests/...`, 교차 영역 변경 시 전체 `npm test`, `npm run build`(`prepare-site.mjs`)를 범위에 맞게 실행한다. 이번 인계처럼 문서만 바꾸면 코드 전체 검사·게임 빌드는 필요하지 않다.
4. 배포가 승인된 변경이면 **새 날짜별 릴리스 폴더**에 현재 기준·복구 대상·잠금·검증 결과를 만든다. 오래된 완료 실행기의 버전 상수를 고쳐 재실행하는 방식을 피한다.
5. 진행 중 이벤트를 방해하지 않는 시점을 선택하고, 확인한 기준과 운영이 계속 같은지 재검사한다. 기존 방식의 DO `deferred 30s` 갱신을 참고하되 현재 CLI·환경을 따른다.
6. 공개 HTML/모듈 그래프/이미지, Google 설정, 관리자 접근 거부, 기존 검증 계정의 비공개 해시, 저장소·secret 보존을 확인한다. 상태 변경이 필요한 검사는 격리 환경에서 한다.
7. 실패하면 **이번 실행이 배포한 알려진 버전만** 정해진 기준으로 복원한다. 제3자 새 배포를 과거 버전으로 덮지 않는다. 복구 중 자식 프로세스를 임의 timeout으로 죽이지 않는다.
8. `completed.json`, `verification.json`, `recovery.json`으로 완료·복구를 확인하고 문서와 Git push를 마친다. 이미 완료 표시가 있는 실행기를 다시 돌리지 않는다.

Windows에서는 백그라운드 프로세스 `windowsHide:true` 또는 `Start-Process -WindowStyle Hidden`을 쓴다. 삭제/이동은 절대 경로가 작업 범위인지 확인하고 한 셸에서 수행한다. 셸에 JSON 문자열을 그대로 붙여 명령 이스케이프로 오인하지 않는다.

### 검증 수준을 정확히 말할 것

최신 기능은 Node 회귀·격리 Worker WS/HTTP·공개 자산/권한/해시 검사를 했다. 일부 이전 기능에는 데스크톱 브라우저/모바일 크기 검사가 있지만, 이를 **실제 iPhone의 Instagram 터치·GPU·체감 검증**으로 부르지 않는다. 최근에는 브라우저 제어가 설정에서 비활성화되어 우회하지 않았다. 새 환경에서 사용 가능한 정식 도구를 확인하고, 비활성 보호를 다른 CDP/Playwright 경로로 우회하지 않는다.

## 18. 로컬 의존성·다른 대화/컴퓨터로 인계할 때

- **같은 PC의 다른 대화:** 위 로컬 저장소와 이 문서를 읽으면 코드·문서·로컬 증거를 이어서 볼 수 있다. 채팅 내용이 자동으로 전부 전달된다고 가정하지 않는다.
- **다른 PC/클라우드 환경:** GitHub를 clone하면 추적된 소스·자산·문서를 얻는다. `npm ci`로 의존성을 준비하고 Node/Windows 차이를 확인한다. 기존 Git 변경을 덮지 않는다.
- Git에는 Cloudflare 사용자 DB, 로컬 로그인 세션, `.wrangler`, 비밀 설정, `outputs` 검증 증거, 최종 MP4, 일부 원본 이미지·도구가 없다. 파일이 없다고 기능 미배포로 판단하지 않는다. 필요 시 사용자 허가된 경로로 별도 이관한다.
- 운영 배포·통계 조회에는 해당 환경의 권한이 필요하다. 권한이 없는 새 환경에서 값이나 성공 결과를 추정하지 않는다. 계정 로그인 자체와 코드 이전은 별개다.

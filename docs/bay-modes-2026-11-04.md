# 1개 / 2개 베이 모드 · 2026-11-04

사용자는 기존 1개 베이 도전을 유지하면서 인원이 많을 때 관리자에서 별도의 2개 베이 모드를 선택하기로 최종 결정했다. 두 번째 베이에 새 60초나 이동 준비 시간을 주는 연속 라운드는 아니다.

## 최종 규칙

| 구분 | 1개 베이 뿌시기 | 2개 베이 뿌시기 |
| --- | --- | --- |
| 예고 | 기존 1분 및 3·2·1 | 동일 |
| 제한시간 | 시작부터 60초 | 두 베이와 이동에 합쳐서 60초 |
| 첫 성공 | 200칩 지급 후 종료 | 200칩 즉시 지급, 다음 베이 이동 버튼 표시 |
| 두 번째 성공 | 없음 | 추가 200칩, 총 400칩 지급 후 종료 |
| 두 번째 미완료 | 해당 없음 | 첫 성공의 200칩 유지 |

- 운영자 `/admin` 위쪽에 **1개 베이 뿌시기**, **2개 베이 뿌시기**, **황금 FOUP 찾기 시작**을 표시한다. 자동 15계정/2시간 이벤트는 기존 1개 모드다.
- 첫 베이는 직전 베이를 제외하고 무작위로 고른다. 2개 모드의 다음 베이는 방금 성공한 곳을 제외하고 무작위로 고른다. 두 번째도 멀쩡한 장비 20대로 시작하며 세 번째로 이어지지 않는다.
- 성공 즉시 다음 베이가 활성화되지만 캐릭터를 강제로 이동시키지 않는다. **다음 베이로 바로 가기**를 누르면 기존 방식으로 베이 앞에 도착하고, 남은 시간은 이동/연출 중에도 줄어든다.
- 각 성공 순간 연결된 실제 계정에 200칩을 지급한다. 기존 운영자와 사람 안전팀은 포함, NPC와 검증 계정은 제외한다. 늦게 들어온 계정은 접속 후 발생한 성공 보상만 받는다.
- 보상은 첫 200칩을 포함한 합계다. 2개 성공 시 200+400이 아니라 **200+200=400칩**이며 일반 장비 파괴 보상은 별도다.
- 안전팀 NPC는 도전 중인 베이와 짧은 성공 표시 중인 직전 베이 모두에 들어오거나 그 안의 이용자를 붙잡지 않는다. 사람 안전팀의 역할은 기존과 같다.
- 황금 FOUP 정기 시간 및 이벤트 상호 배제는 유지한다. 2개 모드도 같은 60초 마감이므로 추가 정시 충돌이 생기지 않는다.

## 성공 표시와 조작

- 1개: 민트색 `베이 클리어!`, `+200칩 적립`, 누적 200칩.
- 2개: 금색 `더블 클리어!`, 작은 색종이 8개, `+200칩 적립`, 누적 400칩. 개인의 실제 누적 지급액이 다른 경우 별도로 표시한다.
- 지갑 지급 확인 및 장비 붕괴 완료 뒤 기존 3초 성공 탑뷰를 사용한다. 다음 베이로 이동하면 탑뷰를 취소하며, 늦게 온 지급 표시 때문에 이전 베이로 카메라를 다시 돌리지 않는다.
- 별도 평상시 카메라 변경은 없다. `src/explorer.js`는 사용자가 원복한 `b1bd6fd`와 같고 사진/영상을 서버에 저장하지 않는다.

## 저장과 호환

- 이벤트의 최초 ID와 시작/종료 시각을 유지한다. `bayLimit`은 1 또는 2이고, 값이 없는 이전 이벤트/요청은 1개 모드로 취급한다.
- 성공한 베이와 성공 순번을 저장하고 각 지급 ID를 구분한다. 보상·장비 상태·이벤트 상태가 기존 원자 저장 배치에 함께 확정된다. 재시작/재접속/재요청으로 반복 지급하지 않는다.
- 지갑의 기존 값은 보존하고 이벤트에 참여한 경우에만 이번 도전 지급액을 작은 추가 필드로 저장한다. 전체 계정 조회나 신규 예약 작업을 추가하지 않는다.
- 운영자 API는 같은 Origin 및 기존 쿠키만 허용한다. `bayCount`는 정수 1/2만 허용하며, 같은 요청 UUID로 모드를 바꾸는 요청은 거부한다.

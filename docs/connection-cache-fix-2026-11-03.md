# 새로고침 뒤 연결 대기와 파일 버전 일치 — 2026-11-03

사용자가 이전 접속 개선 뒤에도 iPhone Instagram에서 화면은 열리지만 `팹 연결 중`, 개인 기록 `…`, 이름 `연결 중`으로 오래 남는 사진을 보냈다. 예전에는 새로고침하면 바로 연결됐다고 설명했다.

## 관찰과 한계

- 이번 운영 측정은 설정 316ms, 랭킹 162ms, 같은 기존 검증 계정의 welcome 5회 537/325/521/277/485ms였다. 현재 DB 조회가 모든 접속을 오랫동안 지연시키는 현상은 이 측정에서 관찰되지 않았다.
- 운영 실시간 로그에서 **프로토콜 18로 `/api/room`에 반복 접속하여 HTTP 409로 거절되는 요청**을 확인했다. 현재 프로토콜은 20이다. 로그에는 개인 ID·쿠키·닉네임을 저장하지 않았으며 이 요청을 사용자의 특정 휴대폰이라고 식별하지 않았다.
- 기존 클라이언트는 WebSocket 연결의 HTTP 409 본문을 읽지 못해 다시 연결을 반복했고, 화면은 `연결 중`으로 돌아갔다. 예전 클라이언트 코드도 확인했으며 다른 버전의 welcome을 받으면 정상적으로 새로고침 필요 상태로 전환한다.
- 이전 빌드는 `main.js`에만 파일 버전 쿼리를 붙였다. 상대 import의 URL에는 전파되지 않으므로 의존 파일이 오래된 캐시에서 들어오는 경우를 방어하지 못했다. **개별 사용자 화면의 모든 지연 원인이 캐시라고 확정하지 않는다.**
- Safari 26에서 동일 호스트의 HTTP 요청과 WebSocket 시작이 겹칠 때 실패하는 현상은 [WebKit 공식 이슈 302823](https://bugs.webkit.org/show_bug.cgi?id=302823)에 재현 기록이 있다. 사용자의 현재 OS에서 같은 결함인지 직접 확인하지 못했으므로 아래 시작 순서 변경은 예방 조치로 구분한다.

## 변경

- 모든 로컬 JS와 모듈 Worker의 import URL에 동일한 전체 빌드 해시를 넣는다. 하위 파일 하나만 바뀌어도 전체 해시가 바뀌어 프로토콜·꾸미기·이름표 등이 한 버전으로 로드된다. 기존 모듈 구조와 vendor 버전은 유지하며 게임 전체를 새 단일 번들로 바꾸지 않는다.
- 진입 HTML은 `Cache-Control: no-store`로 전달한다. JS/vendor는 기존 정적 배포 경로를 사용한다.
- 프로토콜이 다른 WebSocket 요청에는 연결을 열어 현재 버전의 최소 welcome을 전달한 뒤 닫는다. 예전 클라이언트도 이해하는 방식이므로 재접속 루프 대신 새로고침 안내가 나온다. 이 경로는 방에 입장하거나 프로필을 생성·변경하지 않는다.
- 설정 요청은 모듈 다운로드와 병행하되, WebSocket은 모듈 다운로드가 끝난 직후부터 3D 생성과 병행한다. 같은 호스트의 파일 다운로드와 연결 시작을 분리했다.
- 3D 생성 중 누적되는 연속 프레임은 최신 위치와 모든 FOUP 변경을 합쳐 보관한다. 100프레임을 받아도 64메시지 제한 때문에 정상 연결을 버리지 않는다. 지갑·명단 메시지는 순서를 유지하며 전체 메모리/20초 만료 제한도 유지한다.
- 페이지를 나가거나 새로고침하면 기존 소켓을 닫고, 브라우저의 뒤로 가기로 복원되면 한 번만 새로 연결한다. 다른 탭에서 이미 접속한 상태는 되찾아 오지 않는다. [MDN의 WebSocket 페이지 수명 관리](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_client_applications)를 참고했다.
- 초기 접속에서 error만 발생하고 close가 오지 않는 경우에는 8초 타이머를 끝까지 기다리지 않고 재시도한다. 실패가 반복되면 대기 시간을 늘려 요청 폭주를 막는다.
- 방 `FAB-A-v20`, 프로토콜 20, 세션 쿠키, 운영자 ID, 저장된 이름·기록·칩·보유품은 유지한다. 계정 초기화나 DB 마이그레이션은 없다.

## 검증

- 전체 Node 테스트 **329개 통과**. 하위 파일 버전 변경, 정적/동적 import와 Worker URL, 예전 접속 안내, 오류만 오는 소켓, pagehide/pageshow, 다른 탭 우선권, 느린 장면 초기화 중 FOUP/랭킹 보존을 포함한다.
- 실제 인라인 시작 코드와 실제 `main.js`의 DOM 초기화 검사 통과. 첫 프레임, 360대 장비, 저장 위치·99/27 기록, 설정 재사용과 소켓 1회 사용을 확인했다. GPU는 모의 처리했다.
- 독립 로컬 Wrangler에서 현재 빌드의 **66개 모듈/Worker**를 HTTP로 읽어 같은 버전과 내용인지 확인했다. 구버전 18/19는 새로고침 안내 후 1008로 닫히며 프로필을 생성하지 않는다. 현재 버전은 24/32/33ms에 동일 계정·기록·지갑으로 다시 접속했다. 이는 개발 PC 로컬 측정이다.
- 실제 iPhone/Instagram에서 새 버전의 체감 속도와 GPU 화면은 후속 확인 대상이다. Work 설정에서 브라우저 자동화가 비활성화되어 있어 실제 기기 검증이라고 표현하지 않는다.

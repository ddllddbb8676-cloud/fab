# 2026-11-03 인스타 접속 안정화와 병렬 연결

## 확인한 사실

- 사용자가 실제 iPhone 인스타에서 제출한 독립 점검 결과: 페이지/스크립트 정상, 설정·방 응답 360ms, 진입 모듈 45개 1,344ms, 외부 글꼴 CSS 34ms, 기본 WebGL 125ms. 이 검사는 실제 팹 전체 초기화나 WebSocket 입장까지 검사하지 않았다.
- 이후 실제 게임 화면은 열렸으나 `팹 연결 중`, 임의 닉네임, 개인 0점, 랭킹 대기로 오래 남는 사진을 받았다. 이는 서버 welcome 전의 임시 화면이었다. 사용자는 뒤이어 기존 계정이 복구됐다고 확인했고, 접속 대기를 줄여 달라고 요청했다.
- 수정 전 운영 `http://fab.semitoon.com/` 및 `/api/config`가 HTTPS 전환 없이 HTTP 200으로 응답했다. HTTP 설정 요청은 Secure 없는 새 쿠키를 발급할 수 있었다. 이 진입 경로를 제거했다. 모든 과거 흰 화면의 원인이 HTTP였다고 확정하지 않는다.
- 10:11 KST 기존 검증 계정 입장(welcome: 이름/칩/기록 포함) 4회는 370/223/334/259ms. 기록 있는 방문자 계정 수는 당시 1,238개였으며 전체 방문 계정 수나 실인원 수가 아니다.
- 매 접속 시 전체 프로필을 읽지 않는다. 서버 방 시작 시 `loadRanking`으로 목록을 읽고, 일반 입장은 해당 ID의 저장 프로필을 읽는다. 서버 기동 때 목록 읽기는 규모 영향을 받을 수 있지만 위 측정에서 장시간 정지는 관찰되지 않았다.

## 적용

- 게임 진입 경로(`/`, `/index`, `/index.html`, 점검 화면)와 API는 Worker에서 HTTP를 같은 호스트/경로/쿼리의 HTTPS로 308 전환한다. 전환 응답은 세션 쿠키를 발급하지 않는다. 게임 JS/vendor 파일은 기존 정적 자산 경로를 유지한다.
- 생산 HTML에 기존 CSS 5개와 작은 시작 제어 스크립트를 포함했다. Google Fonts는 기존 글꼴을 유지하되 비차단 방식으로 불러온다. 파일과 글꼴 대기 때문에 처음 안내까지 숨겨지는 의존성을 줄였다.
- HTML 도착 후 설정/쿠키 준비와 게임 모듈 다운로드를 병행한다. 설정 응답 직후 **동일 쿠키로 WebSocket도 미리 열어**, 3D 공간을 만드는 동안 이름·기록·칩 응답을 받을 수 있다.
- 미리 받은 welcome과 후속 변화는 메모리에 순서대로 대기시킨다. 게임 초기화 완료 후 기존 연결 하나를 그대로 인계한다. 최대 64개 메시지/2MiB/20초 제한이며 초과하면 연결을 닫고 정상 입장 경로에서 새 전체 상태를 받는다. 연결을 두 번 소비하거나 계정을 새로 만들지 않는다.
- 실시간 입장 응답이 8초 동안 없으면 해당 연결을 폐기하고 재연결한다. 늦은 이전 연결의 응답은 무시한다. 정원 초과/다른 탭에서 접속/버전 불일치는 기존 규칙을 유지한다.
- 장비 생성 등 초기 작업 중 화면 갱신 시간을 주고, 첫 프레임 완료 후 로딩 화면을 닫는다. 오래 걸리거나 오류가 나면 해당 단계와 같은 창 다시 연결/점검 복사를 표시한다. 점검 정보는 브라우저에서만 표시하며 ID/칩/쿠키를 수집하지 않는다.
- 서버 응답 전 닉네임은 `연결 중`, 개인 기록은 `…`로 표시한다. 임의의 새 이름/0점이 계정 초기화로 오해되지 않도록 했다.

## 보존과 검증

- 방 `FAB-A-v20`, 프로토콜 20, `fab-session-v1`, 프로필 저장 키, 소유자 지정 권한, 기존 칩/보유/닉네임/누적 기록 유지. DB 복원·삭제·계정 재설정 없음. 분홍 방진복은 복구 기준에 따라 재추가하지 않았다.
- 조이스틱·이동 속도·카메라와 카탈로그 변경 없음. 카카오/구글 로그인도 보류 유지.
- 전체 Node 테스트 **306개 통과**. 초기화 오류/무응답 WebSocket/재연결/오래된 응답 차단/정원 초과/사전 연결 인계·만료·메모리 제한 포함.
- 실제 장면/방 모델과 DOM으로 초기화 및 3프레임 검사: 360대 생성, 기존 이름/99회 파괴/27회 수리/저장 위치 복원, 미리 연 소켓 하나 재사용, 설정 중복 요청 없음. **GPU/WebGL 경계는 대체한 검사로 실제 아이폰 렌더링 검증이 아니다.**
- 생산 HTML의 실제 인라인 시작 코드 실행, CSS 순서·내용, 비차단 글꼴, 설정/모듈/실시간 연결 병행을 DOM으로 검증했다.
- 운영 진입 경로 5개 HTTPS 308 및 새 쿠키 없음 확인. 운영 파일 10개 일치. 기존 검증 쿠키 그대로 입장 3회, 이름·기록·지갑 동일 확인(425/324/390ms).
- 실제 운영 서버에 미리 연결해 1.5초의 화면 준비를 모의한 검사: 서버 welcome 272ms, 화면 준비 후 인계 2ms, WebSocket 1개 재사용. **이 숫자는 실제 아이폰 전체 접속 시간이 아니다.**
- 실제 Instagram 새 버전의 체감 속도/간헐 재현은 후속 사용자 확인 대상. 모든 접속이 즉시 끝난다고 보장하지 않는다.

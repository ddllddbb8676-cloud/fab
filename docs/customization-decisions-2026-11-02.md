- 사용자가 무료 기회를 사용한 사람에게 상점에서 1,000칩짜리 변경권을 팔도록 추가 요청했다. 가격은 `src/nickname-policy.js`의 서버/화면 공용 상수를 사용한다.
- `꾸미기 · 내 옷장 → 상점` 아래쪽에 변경권을 표시한다. 보유 중에는 내 옷장에서도 `이름 바꾸기`를 사용할 수 있다. 상시 게임 HUD는 추가하지 않는다.
- 구매 확인 후 1,000칩을 차감하고 1장을 보관한다. 무료 기회를 먼저 사용해야 구매할 수 있다. 이름 최종 확정 시에만 1장을 사용하며 사용 후 재구매할 수 있다.
- `나중에 사용하기`, 새로고침, 재접속, 중복/금지 이름, 저장 재시도 때문에 변경권이 사라지지 않는다. 같은 이름으로 변경권을 낭비하는 것도 막는다.
- 한 장 보유 중에는 추가 결제하지 않는다. 구매 횟수를 대조하여 오래된 구매/사용 요청의 재전송이 추가 차감으로 이어지지 않도록 했다.
- 기존 wallet에 `nicknameTickets`, `nicknamePurchases`를 추가한다. 구 프로필은 두 값이 없으면 0으로 취급한다. 구매/칩 차감, 변경/티켓 소모는 각각 같은 프로필 저장으로 반영한다.
- 운영자에 의한 이름 교체는 보유 변경권을 소모하지 않는다. 변경권만 구매했어도 미구매자 꾸미기 안내를 중지하고, 사용 후에도 구매 이력을 유지한다.
- 소유자의 지정 이름은 유지하므로 소유자 계정에는 변경권 판매를 표시하지 않는다.

## 후속 적용: 모든 칩 획득 표시와 효과음

- 사용자는 EMO 보상부터 요청한 뒤 모든 칩 적립 순간에 적용하도록 확장했다. 파괴 `+5C`, 수리 `+3C`, FOUP 던지기 `+1C`, 실제 OHT 탑승 10초마다 `+1C`를 표시한다.
- 본인 이름표 위에 진한 테두리의 금색 글씨가 약 1.4초간 떠올랐다 사라진다. 카메라가 멀어져도 읽을 수 있는 화면 글자 크기를 유지하고, 이동/터치를 가로채지 않는다. 동시 표시는 최대 3개이며 동작 줄이기 설정을 따른다.
- 0.58초짜리 짤랑 소리를 기존 효과음 믹서에 추가했다. 효과음 끄기, 숨겨진 탭, 오디오 중단 상태를 따른다. 다른 소리가 많아도 기존 4개 재생 한도 안에서 보상 소리를 우선한다.
- 공용 `grantChips`에서 기존 wallet에 누적 획득량 `earnedChips`를 함께 기록한다. 클라이언트는 소비 가능한 잔액의 차이가 아니라 이 값의 증가를 이용한다. 구매와 적립이 한 응답에 함께 있어도 보상을 놓치지 않는다. 실제 적립/지갑 저장 경로와 보상 수치는 유지했다.
- 최초 지갑 로드, 과거 소급액, 재접속은 기준값으로만 받아 효과를 반복하지 않는다. 중복/이전 응답, 실패한 행동, NPC/다른 사람의 적립, 구매/닉네임 변경에는 획득 효과를 내지 않는다. 소유자 무제한 계정도 본인의 행동 보상에는 효과가 나온다.
- 전체 자동 테스트 231개 통과. 기존 안전팀 재접속 테스트의 무작위 NPC 이름 충돌은 운영과 같은 닉네임 예약을 사용하는 테스트 구성으로 수정했다. 게임의 안전팀 동작은 바꾸지 않았다.
- 로컬 Worker의 실제 WebSocket에서 파괴 → 수리 → FOUP 던지기 → 실제 OHT 10초 탑승을 수행하여 `[5, 3, 1, 1]`을 한 번씩 수신했다. 타인 화면은 0회이며 재접속 후 10칩 복원에 추가 효과가 없었다.
- 문법 검사, 브라우저 모듈 그래프, 정적 빌드, Worker dry-run 통과. 운영의 HTML/JS/CSS 5개가 배포 파일과 일치하고 새 서버의 획득 카운터 응답을 확인했다. 운영 방문자의 기록은 테스트 목적으로 수정하지 않았다.
- 모바일 실기기의 실제 글자 위치와 음량은 직접 확인하지 못했다. 브라우저 도구가 비활성화된 상태이므로 코드/통신/오디오 생성 및 음소거 검증과 실기기 체감은 구분한다.

## 후속 수정: 파괴 후 보상, 선명한 이름표, OHT 탑승

- 파괴 보상 5칩의 실제 적립은 그대로 즉시 처리한다. `+5C` 표시와 짤랑 소리는 해당 장비의 붕괴 및 폭발 카메라가 끝나고 본인 캐릭터가 다시 보일 때 낸다. 수리·FOUP·OHT 보상은 기존처럼 즉시 표시한다.
- 지갑에 `earnedDestructionChips`와 `lastDestructionId`를 함께 저장하여 파괴 보상만 분리한다. 기존 필드가 없는 지갑은 0부터 세며 재접속/초기 지갑/중복 응답에 효과를 반복하지 않는다. 방/프로토콜/저장 키는 유지한다.
- 본인 이름표는 화면 좌표에 맞춘 진한 청록색 16px 글자로 표시하여 넓은 시야와 모바일 캔버스 해상도 제한에서도 크기를 유지한다. 주변 이름표는 안개 영향을 없애고 글자 크기 14–18px 범위를 유지하며 18m까지 표시한다. 머리 장식 위 간격과 주변 인물의 가림 처리는 유지한다.
- OHT 탑승은 서버가 실제로 멈춘 차량 위치와 접근점을 응답하고 클라이언트가 그 지점까지 걷는다. 300ms 지연 보간된 화면 좌표를 목표로 삼아 도착 후 다시 가까이 오라는 오류를 수정했다. 같은 OHT를 다시 눌러도 진행 중 예약을 유지한다.
- 로드포트가 없는 구간에서는 “로드포트가 있는 곳에서 타야 해요”라고 안내한다. 실제 대상 장비가 파손됐을 때만 파손 안내를 낸다. 탑승 지점에 도착하지 않은 요청에는 로드포트 앞으로 오라는 별도 안내를 사용한다.
- 전체 자동 테스트 238개 통과. 화면상 OHT가 실제 위치보다 2m 뒤에 있는 경우의 걷기→탑승, 로드포트/파손 오류 구분, 파괴 보상 대기 중 다른 보상 즉시 표시, 이름표 투영 크기·숨김·이름 갱신을 포함한다.
- 로컬 Worker의 실제 WebSocket에서 파괴→수리→FOUP 던지기→서버가 확정한 위치로 OHT 탑승→10초 보상 `[5,3,1,1]`, 파괴 보상 메타데이터, 재접속 10칩 복원을 확인했다. UI 소리/실기기 화면의 직접 확인은 여전히 미완료다.
- 문법 검사, 브라우저 모듈 그래프, 정적 빌드, Worker dry-run을 통과했다. `immediate` 방식으로 운영 배포한 뒤 주요 HTML/JS/CSS 10개가 로컬 dist와 바이트 일치하고 새 지갑의 파괴 보상 카운터가 0임을 확인했다. 운영에서 게임 행동/구매를 테스트하지 않았다.

# 누적 파괴 칭호와 운영자 표시

사용자가 누적 파괴 대수별 칭호안을 승인했고, FAB짱 세미에게는 별도로 `운영자`를 표시해 달라고 요청했다.

| 누적 파괴 | 칭호 | 색상 |
| ---: | --- | --- |
| 1 | 새싹 파괴자 | 짙은 회색 `#4b5963` |
| 5 | 꼬마 사고뭉치 | 짙은 초록 `#277044` |
| 20 | 버튼 장인 | 파랑 `#205fa8` |
| 50 | 사고 대장 | 남색 `#334a8b` |
| 100 | 장비의 천적 | 보라 `#7442a6` |
| 300 | 라인 파괴자 | 진분홍 `#b42c75` |
| 500 | 팹의 재앙 | 짙은 주황 `#a64b17` |
| 1,000 | 전설의 파괴왕 | 진한 금갈색 `#886015` |
| 3,000 | FAB 파괴신 | 진한 빨강 `#b5253c` |

- 기존 `brokenCount`가 획득 기준이다. 과거 파괴 기록도 즉시 인정하며, 실패한 파괴·수리·FOUP 파손은 포함하지 않는다. 칩 차감/추가 지급은 없다.
- 기본은 최고 칭호 자동 표시다. `메뉴 → 꾸미기 → 칭호`에서 이전에 얻은 칭호 선택, 숨기기, 자동 표시 복귀가 가능하다. 미획득 칭호와 다음 칭호까지 남은 대수도 보여준다.
- 본인 칭호는 닉네임 위에 12px, 주변 칭호는 약 11~14px로 표시한다. 기존 닉네임 크기/위치, 머리 장식 위 여백, 근처 10명/18m 표시 제한을 유지한다. 사용자 모바일 화면 제보를 반영해 두 줄을 가운데 정렬했다.
- 후속 요청으로 NPC 34명도 100대 이하 칭호를 하나씩 착용한다. 파괴 담당은 20/50/100대, FOUP 담당은 5/20대, OHT 담당은 1/20대, 나머지는 1/5대 칭호를 ID별로 고정 배정한다. 모든 접속자/재시작에서 동일하며 NPC의 실제 파괴 기록과 랭킹 점수는 바꾸지 않는다.
- FAB짱 세미의 지정 계정은 항상 진분홍 `운영자`로 표시한다. 서버의 기존 `FAB_OWNER_VISITOR_ID`와 전체 ID가 일치할 때만 적용하며, 이름/클라이언트 입력/저장된 무한 칩 플래그로 권한을 만들 수 없다. 이 계정에는 일반 칭호 선택/숨기기를 허용하지 않는다.
- 동일 프로필에 `titlePreference`만 추가한다. 기본값은 `auto`, 숨김은 `hidden`, 고정 선택은 획득한 칭호 ID다. 사용자 ID·이름·파괴/수리·칩·인벤토리·랭킹·장비/FOUP 상태를 보존한다.
- 방 `FAB-A-v20`, 프로토콜 20, 기존 저장 키를 유지한다. 위치 패킷의 마지막에 현재 칭호 ID 한 칸만 추가한다. welcome/ack에 개인 선택 상태를 보내며 서버 검증 및 저장 후 공유한다.

## 검증

- 전체 자동 테스트 267개 통과. 신규 검증: 단계 경계, 기존 기록 적용, 성공한 파괴만 승급, 이전 칭호 고정/숨김, 운영자 사칭 거절, 저장/재시작, 기존 데이터 보존, 다른 접속자 전파, 풀 재사용 시 다른 사람의 칭호 잔류 방지.
- NPC 칭호 후속 변경 후 관련 20개 테스트 추가 실행 통과. 34명 모두 100대 이하 칭호, 재시작 시 동일 배정, NPC 점수와 사용자 기록 불변을 확인했다.
- 실제 Three.js 이름표에서 닉네임 크기/기준점 유지, 헬멧·토끼귀·왕관의 모든 자세에서 이름표 여백, 본인 칭호 색/이름 변경/숨김을 검증했다.
- Node DOM 검증에서 상점/옷장/칭호 탭 전환, 시착 유지, 미획득/오프라인 선택 거절, 무료 선택, 운영자 고정을 확인했다. 미리보기는 머리 장식과 칭호가 잘리지 않도록 카메라 구도를 조정했다.
- 로컬 Cloudflare Worker의 실제 WebSocket 두 세션으로 5대 파괴에 따른 승급, 상대 화면 패킷, 숨김/이전 칭호 선택, 미획득/운영자 선택 거절, 재접속 및 Worker 재시작 후 이름/기록/칩/선택 유지까지 확인했다.
- 구문 검사, 소스/빌드 번들 검사와 Worker dry-run 통과. 실제 모바일 브라우저/GPU/터치 검증은 수행하지 않았다.
- Git 제외 증거: `outputs/title-full-tests.log`, `outputs/title-ui-qa.json`, `outputs/title-socket-qa.json`, `outputs/title-worker-dry-run.log`.

# 구글 계정 연결

11월 6일 사용자가 구글을 선택했다. 게스트 입장이 기본이다. 팹뿌 전용 웹 클라이언트 ID를 운영 Worker의 `FAB_GOOGLE_CLIENT_ID`에 설정하면 게임 메뉴 및 닉네임 선택 창에 연결 경로가 열린다. ID가 비어 있으면 운영 메뉴는 숨겨지고 `/api/account/google/status`는 `{"enabled":false}`를 반환한다.

2026-11-06 12:35 KST에 운영 버전 `e3859903-2866-49ea-90c8-8325b6553c0b`로 준비 코드를 배포했다. `/account/privacy` 공개, 게스트의 기존 기록 해시, 89개 게임 모듈, 일반 계정의 관리자 접근 차단을 운영에서 확인했다. 현재 구글 버튼은 비활성이다. 등록된 웹 클라이언트 ID와 실제 구글 동의를 사용한 검증이 남았다. 로컬 Worker에서는 별도 브라우저의 일회용 코드, WebSocket·HTTP 양쪽 복구, 운영자 권한 및 연결 해제를 검증했다. 휴대폰 너비 390px에서 코드 입력을 확인했고 실제 iPhone에서 구글 로그인을 검증한 것은 아니다. 전체 검사 608개 통과, 1개 건너뜀. 배포 검증 기록은 `outputs/google-link-release/verification.json`이다.

## 공개 설정

1. 팹뿌용 Google Auth Platform에서 외부 이용자용 브랜딩과 지원 메일을 설정한다. 홈페이지는 `https://fab.semitoon.com`, 구글 연결 개인정보 안내는 `https://fab.semitoon.com/account/privacy`이다. 운영 공개 시 대상 및 Google이 요구하는 도메인 확인 사항을 점검한다.
2. 웹 애플리케이션 클라이언트의 승인된 JavaScript 원본에 `https://fab.semitoon.com`을 등록한다. 버튼의 JavaScript 콜백을 사용한다. 공개 클라이언트 ID만 Worker 변수로 지정한다. 클라이언트 보안 비밀번호와 사용자 인증 토큰을 저장소나 로그에 넣지 않는다.
3. 배포할 때 기존 Durable Object와 운영자·통계 제외 바인딩을 보존한다. 운영 키로 일반 브라우저에서 동의, 기존 캐릭터 연결, 다른 브라우저 복구를 검증한다. 본인 확인 없이 운영자 캐릭터를 임의로 연동하지 않는다.

## 이용 흐름

- 메뉴 → 설정 → 구글 계정 연결. 새 기기의 닉네임 창에서도 연결한 캐릭터를 불러올 수 있다.
- 일반 브라우저에서는 구글 인증 후 대상 닉네임과 기록을 확인한다. 인스타 등 내장 브라우저에서는 Safari/Chrome으로 `/account#code`를 열어 받은 코드를 플레이하던 브라우저에 붙여 넣는다. 외부 브라우저 인증만으로 캐릭터 전환이나 연결은 일어나지 않는다.
- 구글 인증은 서명, 발급자, 대상 앱, 유효 시간, 일회용 nonce를 서버에서 확인한다. 영구 연결에 쓰이는 구글 식별자는 `sub`의 해시다. 원래 세션 쿠키와 프로필은 유지하고 복구한 기기에만 별도 HttpOnly 쿠키를 발급한다. 이 쿠키는 원래 기기의 세션에도 묶이고 30일 뒤 만료된다.
- 구글 계정과 캐릭터는 각각 하나씩만 연결된다. 다른 브라우저에서 가져온 코드는 5분 안에 한 번 사용하며, 미리보기한 기기가 최종 확인한다. 가린 이메일 표시는 코드와 함께 만료된다. 데이터베이스에서 만료된 임시 자료는 다음 인증 시작 때 정리한다. 프로필을 복사하거나 지갑·아이템을 재지급하지 않는다.
- 기기의 원래 캐릭터로 돌아갈 수 있다. 같은 구글 계정으로 재인증해 연결을 해제하면 다른 기기의 복구 세션도 해제된다. 연결된 프로필의 게임 초기화는 해제 후 진행한다.

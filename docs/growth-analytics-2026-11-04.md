# FAB 이용 흐름 분석 인수인계 — 2026-11-04

**상태: 구현과 로컬 검증 완료, 운영 배포 준비 완료. 아직 운영에는 반영하지 않았다.** 기존 운영자 현황에 분석 영역을 추가한다. 배포 후 아래 기록란을 갱신한다. 실제 iPhone/Instagram 앱 내부 브라우저 화면 및 체감 성능은 미검증이다.

## 목적과 변경 범위

- 운영자가 재방문, 실제 놀이, 꾸미기 구매, 접속 품질을 알아볼 수 있도록 앞으로의 관측을 기록한다. 과거에 수집하지 않은 방문일·플레이 시간·판매 시점을 만들어 소급하지 않는다.
- 기존 `/admin`의 현재 접속자, 일별 고유 계정 꺾은선, 시간별 최고 동시 접속, 보유품 집계, 접속 닉네임과 걸어가기 기능을 유지한다. 분석 영역만 추가하며, 게임 화면에 새 통계 패널을 넣지 않는다.
- 게임의 계정 ID·닉네임·기록·지갑·보유품을 분석 때문에 변경하지 않는다. 관리자 조회는 게임 참가자를 생성하지 않는다. 카카오/구글 로그인은 이번 범위에 없다.
- 일반 이용 분석에서 운영자, 명시된 검증 계정, NPC를 제외한다. 안전팀 역할을 맡은 실제 일반 계정은 포함한다. 기존 **실시간 접속 명단에는 운영자도 표시**되므로, 기존 현황과 신규 분석의 제외 기준이 다르다.

## 구성과 게임 응답 보호

```text
게임 클라이언트 ── 기존 게임 요청 ── FabRoom / 기존 프로필 저장
       │                              │
       │ 별도 /api/telemetry           └─ 작은 관측을 메모리 대기열에 추가
       │                                  (게임 요청에서 전송/저장을 기다리지 않음)
       ▼                              ▼
         FAB_ANALYTICS → FabAnalytics
         제한된 배치 수신 / 중복 제거 / 별도 분석 저장
                       │
               운영자 /api/admin/metrics
               기존 현황 + growth 응답 병합
```

- [server/growth-relay.js](../server/growth-relay.js): 게임 쪽 관측 전달기다. 일반 전송은 5초 간격, 대기열은 512개 또는 약 110KB에서 제한한다. 이동 관측은 계정당 1초에 한 번만 전달한다. 연결 종료 등에서는 남은 배치 전송을 요청한다. `waitUntil`로 처리하고 게임 응답 경로에서 기다리지 않는다.
- 전송은 동일한 배치 ID로 한 번 재시도하며 기본 시도 시간 제한은 2초다. 대기열 초과·실패·60초보다 늦게 도착한 관측은 누락으로 처리한다. 누락 수가 전달되면 분석 응답에 한도/누락 안내를 붙인다. 실패한 분석을 이유로 게임 명령이나 칩 지급을 되돌리지 않는다.
- [server/analytics-worker.js](../server/analytics-worker.js): 신규 `FabAnalytics` Durable Object에서만 분석 복원·집계·저장을 수행한다. 저장은 집계값과 수신 배치 ID를 같은 트랜잭션으로 커밋하여 응답 유실 후 재시도에 따른 중복을 막는다. 저장 실패 후에는 마지막 커밋 상태를 다시 읽고, 복원이 실패하면 분석 요청만 일시 실패시킨다.
- 게임의 `FabRoom`과 분석의 `FabAnalytics`는 서로 다른 인스턴스·저장소다. 분석 콜드 스타트의 저장소 조회, 계정 통계 순회, 관리자용 분석 스냅샷 계산을 게임 DO 안에서 실행하지 않는다. 저장소 복원도 한 번에 500개 키씩 읽는다.
- [server/worker.js](../server/worker.js)는 기존 관리자 현황과 분석 조회를 병행한다. 신규 분석에는 2.5초 응답 시간 제한을 적용한다. 실패하거나 늦으면 `growth: null`과 안내만 반환하고 기존 현황은 표시한다. `/api/telemetry`는 게임 DO를 거치지 않고 분석 DO로 연결한다.
- [src/usage-telemetry.js](../src/usage-telemetry.js)는 게임 시작과 독립된 페이지 단위 대기열을 사용한다. 메모리 대기열 60개, 한 요청 12개/8KiB, 일반 이벤트 20초 배치, 주요 시작 이벤트 약 1.5초 배치, 요청당 6초 제한과 최대 3회 시도다. 실패는 호출한 게임 코드로 던지지 않는다. 탭이 숨겨지거나 페이지가 닫히면 가능한 범위에서 보낸다.
- 서버는 세션 쿠키·같은 Origin·JSON 형식을 검사한다. 요청 본문은 8KiB, 읽기 시간은 3초로 제한하고 계정당 분당 12배치까지 받는다. 운영자 판별 후 클라이언트 수집도 중단하며, 서버에서도 제외 계정을 다시 검사한다.
- 관측 코드의 작은 CPU·네트워크·저장 비용까지 없다는 뜻은 아니다. 게임 경로에서 분석 저장을 기다리지 않는 구조와 크기/시간 제한을 검증한 것이며, 실제 모바일 기기의 추가 부하와 운영 과금은 배포 후 확인해야 한다.

## 개인정보와 보유 기간

- 신규 분석 응답은 집계값만 반환한다. 계정 ID, 페이지 ID, 인증값, 닉네임, 좌표 경로, 원문 오류/스택을 분석 화면에 반환하지 않는다. 기존 현재 접속 닉네임 기능과 운영자 방문 API는 기존 권한 경계를 유지한다.
- 내부 중복 제거를 위해 기존 해시 계정 ID의 일부인 24자리 지문, 날짜별 방문/행동 플래그·활동 시간·첫 연결 시각, 최초 관측 정보, 마지막 관측 시각을 저장한다. 재식별 가능성을 완전히 없앤 익명 통계라고 설명하지 않는다. 원본 계정 ID는 내부 배치 처리 중 전달되지만 이 분석 저장 키/응답에는 그대로 보관하지 않는다.
- 페이지/이벤트는 축약 지문과 제한된 중복 제거 상태를 보관한다. 페이지 원본 URL·전체 referrer·전체 User-Agent·IP·국가를 이 분석 코드가 저장하지 않는다. User-Agent는 거친 브라우저 구분으로만 변환한다.
- `utm_source`/`utm_campaign`은 허용된 영문·숫자·밑줄·하이픈으로 제한된 짧은 태그만 받고, 그 외 referrer는 지정된 서비스명 또는 `external`/`direct`로 줄인다. 유입 태그에 개인 정보나 비밀값을 넣지 않는다. 빌드는 제한된 해시값만 받는다. 오류는 횟수만 보고한다.
- 일별 집계 및 계정별 날짜 기록은 **오늘을 포함한 최근 30개 KST 날짜**만 남긴다. 오래 접속하지 않은 계정 지문도 그 범위에서 정리한다. 계속 활동하는 계정의 축약 지문과 최초 관측 메타데이터는 최근 기록과 함께 남을 수 있다.
- 페이지 중복 제거 기록은 최초 관측 후 약 24시간에 정리한다. 릴레이 재시도 수신증은 최근 약 2분, 최대 512개다. 프로필 비교 기준은 최대 512계정의 메모리 상태이며 별도 지갑/구매 원장을 영구 복제하지 않는다.
- 정리는 관측·조회·저장 과정에서 수행한다. 별도 예약 삭제 작업이나 매일 자정 삭제 알람을 만든 것은 아니므로, 완전히 유휴 상태이면 다음 요청까지 물리적 삭제가 늦어질 수 있다. 조회 결과에서는 만료된 날짜를 제외한다.
- 위 보유 기간은 신규 분석 저장소에 해당한다. 사용자 본래 게임 기록·칩·보유품의 보유 정책을 변경하지 않는다. 인프라 자체의 요청 처리/로그 정책 전체를 이 코드만으로 보장하지 않는다.
- 관리자 HTML/API는 기존 운영자 세션으로만 접근하며 `private, no-store`, `Vary: Cookie`, 검색 제외 헤더를 유지한다. 텔레메트리 역시 같은 Origin의 유효한 세션만 받고, 신뢰할 수 없는 입력이 칩/게임 상태를 변경하는 데 쓰이지 않는다.

## 부분값·누락·지연 표시

- 수집 시작 날짜의 `partial`, 오늘의 `ongoing`, 용량/누락을 뜻하는 `limited`를 서로 구분한다. 날짜가 아예 없으면 미수집이며 0으로 채우지 않는다. 필드 누락·표본 없음은 `—`, 실제 관측 0은 `0`으로 표시한다.
- 수집 시작 전 자료는 복구되지 않는다. 분석이 추가되기 전 계정의 과거 방문일을 현재 파괴/수리 기록으로 추측하지 않는다.
- 활동 시간, 프로필 비교 기준, 현재 활동 목록은 메모리 상태도 사용한다. 서버 재시작과 전송/저장 실패로 일부 간격·변화가 누락될 수 있다. 재시작 직후 기준 프로필을 다시 잡으므로 과거 전체 구매가 중복 신규 구매로 잡히지는 않는다.
- 관측 누락이 확인되면 `limited`와 설명을 표시한다. 모든 누락을 완벽하게 탐지하는 로그 시스템은 아니므로, `limited: false`가 사용자 전체를 빠짐없이 관측했다는 보증은 아니다.
- 관리자 새로고침은 기존처럼 화면이 보일 때 60초마다 및 수동 갱신이다. 분석 스냅샷이 늦거나 준비되지 않으면 해당 영역만 확인 대기로 둔다. 이전 값 표시 중에는 갱신 실패/지연을 표시하고, 401/403에서는 이전 분석 내용을 비운다.
- 계정·페이지 수 등 내부 한도에 도달하면 계속 메모리를 키우는 대신 일부 분석을 제외하고 하한임을 표시한다. **최종 상한은 계정 8,000 / 페이지 2,048 / 페이지당 이벤트 128 / 프로필 메모리 기준 512**다. [server/growth-metrics.js](../server/growth-metrics.js)의 `GROWTH_LIMITS`에서 관리한다.

## 배포 인계 — 아직 미완료

1. 최종 한도·저장 크기·상태 복원 검토를 마치고 전체 회귀 검사 및 배포 자산 생성 결과를 기록한다. 신규 클래스 추가는 기존 `FabRoom` 저장소를 교체/초기화하는 변경이 아니어야 한다.
2. 운영 전환 전에는 현재 운영 버전과 검증 계정의 기존 기록/지갑 보존 기준을 확인한다. 프로토콜·기존 방·계정 연결 방식은 이번 분석 작업을 위해 바꾸지 않는다.
3. 배포 후 익명/일반 계정의 관리자 거부, 운영자 분석 응답, 신규 정적 모듈, 신규 분석의 첫 수집 시각 및 한도/누락 표시를 확인한다. 분석 오류·시간 제한 상황에서도 기존 게임 접속/명령과 기존 관리자 현황이 응답하는지 검증한다.
4. 실제 iPhone/Instagram 재접속·플레이·꾸미기·관리자 화면은 별도 검증 상태로 기록한다. 확인하기 전에는 실기기 문제 해결/무부하를 단정하지 않는다.
5. 운영 결과를 이 문서와 기존 인수인계 문서에 갱신한다. 신규 Durable Object 마이그레이션이 포함되므로, 문제가 생겼을 때 과거 배포 구성을 무조건 덮어쓰지 말고 현재 바인딩/마이그레이션과 데이터 보존 상태를 확인한다.

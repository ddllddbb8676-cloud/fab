# 인스타 내부 브라우저 초기 흰 화면 점검과 완화

2026-11-03 사용자는 인스타 내부 브라우저에서만 흰 화면이 오래 유지되고, 게임의 `넓은 세계를 여는 중`도 나오지 않는다고 보고했다. 여러 번 새로고침하면 열리기도 했다.

## 관찰과 원인 판단

- 09:08 KST 무렵 개발 PC에서 운영 첫 페이지 약 0.3초, 기존 검증용 접속자의 WebSocket 입장 약 0.44초, 실시간 프레임 중간 간격 199ms/최대 221ms를 측정했다. 운영 import map의 실제 경로로 요청한 모듈 70개는 모두 정상 응답했다.
- Safari/Instagram 모바일 User-Agent 헤더를 보내도 운영 HTML과 CSS는 200으로 응답했고, 리다이렉트나 Cloudflare challenge는 관찰되지 않았다. 이는 실제 아이폰의 인스타 앱을 구동한 검사가 아니다.
- `src/style.css` 첫 줄에 Google Fonts CSS의 `@import`가 있었다. 해당 CSS 응답은 압축 해제 기준 384,108바이트였으며, 첫 렌더링에 외부 서버 요청이 추가되는 구조였다. 네트워크에서 실제 전송한 압축 용량을 뜻하지 않는다.
- 외부 CSS import는 첫 화면 렌더링을 지연시킬 수 있다. [Google의 리소스 로딩 설명](https://web.dev/learn/performance/optimize-resource-loading)을 참고했다. 이 의존성은 확인했지만 사용자의 순간적인 인스타 지연 원인으로 확정하지는 않았다. 앱이 HTML을 받기 전 생기는 지연은 이 수정만으로 해소된다고 보장할 수 없다.

## 변경

- 외부 Google Fonts 요청을 제거하고 iOS/Windows의 기본 글꼴을 사용한다.
- 운영 빌드 시 기존 스타일 파일 5개를 순서와 내용 그대로 HTML에 포함한다. 로딩 안내를 그리기 위해 별도 스타일시트를 기다리지 않는다. 개발 원본 HTML과 게임 본문·스크립트·버튼 마크업은 그대로다.
- 초기 스타일에 외부 요청이나 `@import`를 다시 추가하면 빌드에서 감지한다. 운영 HTML은 49,833바이트, 로컬 Brotli 압축 기준 11,344바이트다.
- 게임 로직·사용자 ID·기록·칩·구매·기존 방과 프로토콜 20은 변경하지 않았다.

## 검증과 배포

- 전체 Node 테스트 282개, 빌드 스크립트 구문 검사, 정적 빌드, Wrangler 사전 검사 통과.
- DOM 파싱으로 스타일 5개의 내용과 적용 순서, 게임 본문 전체, 로딩 안내를 확인했다. 운영 HTML에 외부 글꼴 요청과 렌더링을 막는 스타일시트 링크가 없음을 확인했다.
- 운영 버전: `17262981-a80b-49be-9d03-86318013b2d3`.
- 2026-11-03 09:38 KST: Safari/Instagram User-Agent 헤더로 받은 운영 HTML·CSS가 빌드와 일치했다. HTML 응답은 각각 279ms/96ms였다. 이는 사용자의 인스타 첫 화면 표시 시간이나 개선율을 측정한 값이 아니다.
- 실제 아이폰 인스타의 해결 여부는 사용자 재확인이 필요하다. 현재 Work 설정에서 로컬 브라우저 사용이 꺼져 있어 브라우저 자동 재현도 수행하지 못했다.
- 상세 증거는 Git 제외 `outputs/loading-delay-2026-11-03/`에 있다.

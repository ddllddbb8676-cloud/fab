# 운영자 이벤트 시작 버튼 · 2026-11-04

사용자가 기존 운영자 계정으로 관리자 페이지에서 베이 뿌시기와 황금 FOUP을 시작하도록 요청했다. 최초에는 `/admin` 위쪽에 두 버튼을 추가했고, 21:39 KST부터는 **1개 베이 뿌시기 / 2개 베이 뿌시기 / 황금 FOUP 찾기 시작** 세 버튼이다. 최신 모드·안전팀 제외와 운영 상태는 `docs/bay-modes-2026-11-04.md`를 참고한다. 카메라 원복과 기존 기록·칩·구매품은 유지한다.

## 동작

- **베이 뿌시기 시작**: 누르는 즉시 전체 1분 예고. 직전 이벤트 베이를 제외한 17개 중 무작위로 정한다. 3·2·1 뒤 장비 20대가 모두 멀쩡한 상태에서 60초 도전한다. 운영자 시작은 15계정 및 2시간 대기 조건을 건너뛰고, 다음 자동 이벤트 대기 기준은 새 시작 시각으로 갱신한다.
- **황금 FOUP 찾기 시작**: 20개를 즉시 생성하고 10분 진행한다. IN +200 / 던지기 +50 / 청소 +10 및 한국 시간 08·12·16·20시 정기 진행은 그대로다. 수동 시작은 마지막 정기 슬롯 표시를 변경하지 않는다.
- 어느 이벤트든 진행 중이면 다른 시작을 거절한다. 정기 황금 FOUP까지 베이는 2분, 수동 황금은 10분 미만 남으면 시작하지 않아 정기 시간과 겹치지 않는다.
- 안전팀 NPC 4명 모두 준비·도전 중 대상 베이 밖에서 순찰한다. 안에 있던 NPC는 중앙 통로로 이동시키고 경로·추격·붙잡기 모두 해당 베이를 제외한다. 최신 후속 요청으로 실제 이용자가 맡은 안전팀도 예고부터 일반으로 전환하고 두 모드 모두 끝날 때까지 새 선정하지 않는다.
- 일반 파괴·수리 NPC 제외와 성공 시 접속 계정 +200칩, 성공 탑뷰 3초는 기존 이벤트 규칙을 유지한다. 평상시 카메라/조이스틱은 `b1bd6fd:src/explorer.js`와 동일하다.

## 권한·저장·부하

- `/api/admin/events`는 기존 운영자 쿠키만 허용한다. Worker 및 FabRoom 양쪽에서 확인한다. 일반/익명 요청은 403이다. POST는 같은 Origin의 JSON 요청만 받고 본문은 최대 512바이트/3초로 제한한다.
- 클라이언트는 응답이 끊긴 요청의 UUID를 재사용한다. 서버는 최근 32개 시작 요청의 결과를 기존 이벤트 체크포인트에 저장하며, 저장 완료 후 성공 응답한다. 같은 요청의 재전송과 동시 요청은 이벤트를 다시 시작하지 않는다.
- 관리자 상태 GET은 메모리의 이벤트 정보만 조회한다. 새 계정을 만들거나 개인 프로필을 수정하지 않는다. 관리자 화면이 보일 때만 15초 간격 조회하고 초 표시만 로컬에서 갱신한다. 기존 전체 통계 조회 간격은 그대로다.
- 기존 방 `FAB-A-v20`, 프로토콜 20, `v2-growth-analytics`와 두 DO 네임스페이스·소유자/검증 제외 secret을 유지한다.

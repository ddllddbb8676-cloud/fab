# 전체 보기의 바닥 얼룩 수정

사용자가 2026-11-02 모바일 화면에서 전체 보기의 바닥이 얼룩덜룩해지고 짙은 줄이 번갈아 나타나는 현상을 제보했다. 바닥 색상 변경 요청이 아니라 렌더링 겹침 수정 요청이다.

## 수정

- 기존 바닥 표면 `y=-0.02`와 짙은 받침 상면 `y=-0.04`가 2 cm 차이로 겹쳐 있었다. 전체 보기에서도 걷기용 near `0.08`을 쓰면서 카메라는 수백 m 멀어졌다. 기존 투영 행렬의 24비트 깊이 계산에서 두 면이 같은 값으로 판정되는 경우를 재현했다. [Three.js 카메라 설명](https://threejs.org/manual/pages/cameras.html)의 깊이 정밀도 원리와도 일치한다.
- `src/scene-depth.js`: 전체 보기에서 FAB과 입구·선로·효과를 포함한 여유 경계까지의 거리를 계산하여 near/far를 조정한다. 회전·확대·축소·이동 후 매 프레임 culling/render 전에 갱신한다.
- 다른 시점에서는 기존 near `0.08` / far `420`을 정확히 복원한다. 위치, 화각, 이동 속도, 조이스틱, 회전·확대 조작은 유지한다.
- 받침의 보이지 않는 상면만 제거하여 바닥과의 중복을 없앴다. 바닥의 텍스처·색상·높이와 받침의 옆면·아랫면은 유지한다. 전체 장비, OHT, 캐릭터의 원래 색과 조명은 변경하지 않는다.
- 본인 이름표는 모든 방문자에게 동일한 코드로 각자의 현재 위치에 표시된다. 전체 보기에서 다른 사람의 이름표를 모두 펼치지는 않는다. 가까운 주변 사람의 이름표 표시는 기존대로 유지한다.
- 서버, 사용자 식별, 프로필·기록·칩·아이템, `FAB-A-v20` 방과 프로토콜 20은 변경하지 않았다.

## 검증

- 전체 자동 테스트 248개 통과. 신규 검사 4개는 기존 깊이 충돌 재현과 수정 후 분리, pan/orbit/zoom/화면 비율 변경 시 FAB 잘림 방지, 일반 시점의 원래 투영 복원, 받침 상면 제거 및 옆면·아랫면 보존을 확인한다.
- 구문 검사, 소스 및 `dist` 모듈 그래프 검사, 정적 빌드 86개 파일, Worker dry-run 통과.
- 현재 Work 설정에서 브라우저 사용이 비활성화되어 실제 iPhone/Instagram WebView의 화면은 직접 검증하지 못했다. 자동 검사 결과와 실기기 화면 검증을 구분한다.

# 운영자에게만 보이는 NPC 표시 — 2026-11-03

사용자는 NPC와 실제 이용자를 자신만 구분하고 싶다고 요청했고, 운영자에게만 보이도록 확인했다.

- 기존 서버 `welcome.privileges.unlimitedChips === true` 권한을 받은 화면에서만 주변 NPC의 이름 오른쪽에 작은 파란색 `NPC` 배지를 그린다. 이 권한은 서버에 설정된 운영자 ID에만 부여되며 이름·칭호·안전팀 역할로 추정하지 않는다.
- 상주 `resident:<숫자>`와 안전 순찰 `safety:<숫자>`를 모두 표시한다. 안전팀 역할을 맡은 실제 이용자는 NPC로 표시하지 않는다.
- 일반 이용자, 연결 전, 연결 끊김/교체/재접속 대기에는 배지가 없다. 재접속 후 서버 권한을 다시 확인한다.
- 다른 이용자에게 전송하는 이름·칭호·명단은 바꾸지 않는다. 운영자 화면의 이름표 텍스처만 확장하고 글자 크기와 이름/칭호의 가운데 정렬을 유지한다. 기존 주변 이름표 거리·표시 개수·장비 가림 규칙을 따른다.
- 가까운 캐릭터를 그리는 슬롯을 NPC에서 사람으로 재사용할 때 배지를 지운다. 표시 상태가 같으면 텍스처를 다시 만들지 않는다.
- 서버 코드, 프로토콜, 방, 사용자 ID·쿠키·기록·칩·구매 정보, NPC 행동과 이동 조작은 수정하지 않았다. 새 로그인이나 별도 설정 메뉴도 추가하지 않았다.

## 검증

- 전체 Node 테스트 **320개 통과**, 구문 검사와 정적 빌드, Wrangler 배포 사전 검사 통과.
- 신규 회귀 검사는 운영자/일반 화면 구분, 권한 취소, 역할·이름으로 권한을 얻지 못함, 안전팀 사람과 NPC 구분, 캐릭터 슬롯 재사용, 긴 이름에서도 배지 잘림/글자 축소/가운데 정렬 이동 방지를 확인한다.
- 실제 `main.js` 초기화를 DOM과 GPU 모의 환경에서 실행해 일반 접속의 NPC 표시 0개, 운영자 접속의 주변 NPC 표시 5개를 확인했다. 두 경우 기존 기록 99/27, 접속 위치, 360대 장비, 사전 연결 1회 사용도 통과했다. 테스트용 가상 운영자 ID를 사용했고 실제 운영자 접속을 대신하지 않았다.
- 실제 iPhone/Instagram의 GPU 화면과 터치는 아직 직접 확인하지 못했다. 지원 브라우저 자동화가 Work 설정에서 비활성화된 상태이므로 모의 검사와 실기기 검증을 구분한다.
- 검증 파일은 Git 제외 `outputs/owner-npc-full-tests.log`, `outputs/owner-npc-init-ordinary.json`, `outputs/owner-npc-init-owner.json`, `outputs/owner-npc-dry-run.log`에 보관한다.

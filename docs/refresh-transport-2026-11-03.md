# 새로고침 때 연결 종료와 재접속 — 2026-11-03

기존 캐시 수정 이후에도 iPhone Instagram에서 새로고침하면 연결이 자주 끊기고 `연결 중` 상태가 오래 간다는 신고를 받았다. 운영 전후 측정은 같은 기존 검증 계정에 대해 실시했다. 사용자의 휴대폰이나 운영자 계정으로 측정한 것은 아니다.

## 확인한 현상

- 수정 전 운영 서버와 연결한 뒤 클라이언트가 정상 종료를 요청하면, 종료 코드 생략과 1000 지정 두 경우 모두 **4초 동안 종료가 완료되지 않았다**. 같은 조건의 로컬 Wrangler에서도 재현했다. 이 현상만으로 개별 iPhone의 모든 지연을 설명할 수는 없다.
- 서버가 종료 핸드셰이크를 직접 마무리하도록 한 후, 같은 운영 검사의 종료 시간은 **170ms / 176ms**였다. 게임을 여는 전체 시간이 아니다. [Cloudflare의 Durable Objects 안내](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)에서 자동 응답과 명시적 종료 호출의 호환성을 확인했다.
- 기존 클라이언트는 첫 WebSocket이 무응답이면 8초 기다렸다가 다시 같은 경로로 시도했고, 접속 후 열린 상태로 데이터만 끊기는 경우는 감지하지 못했다. 과거 접속 요청이 늦게 도착해 새 연결을 교체하는 상황도 방어하지 않았다.
- 일반 재접속에서 누적 사용자 기록 전체를 조회하지 않는다. 방 최초 생성 시 랭킹을 읽고, 이후에는 자기 프로필을 복원한다.

## 변경

- 운영 게임 HTML을 보낼 때 기존 HttpOnly 세션을 유지하고 첫 방문에만 쿠키를 만든다. 공개 접속 설정과 서버 시간을 초기 HTML에 담아 게임이 별도의 설정 요청을 기다리지 않는다. 진입 HTML은 계속 no-store이고 정적 개발판은 기존 설정 조회를 사용한다.
- WebSocket을 먼저 사용한다. 오류가 나면 즉시, 2.2초 동안 첫 응답이 없으면 같은 방과 쿠키를 쓰는 HTTPS 연결로 전환한다. 성공한 HTTPS 경로는 해당 탭에서 10분간 기억하므로 새로고침 때마다 실패한 경로부터 시도하지 않는다. 연결 후 보이는 화면에서 6초간 데이터가 없으면 정상 종료 신호가 없어도 복구를 시작한다.
- 두 경로 모두 같은 방 입장·정원·운영자 권한·명령·저장 로직을 사용한다. 사용자별 접속 순서를 검사해 낡은 시도가 새 연결을 끊지 못하게 한다. 기존 클라이언트의 WebSocket도 계속 지원한다.
- HTTPS 요청은 같은 출처와 기존 세션을 확인한다. 재전송하는 명령은 순서 번호로 한 번만 실행하며, 저장을 마친 응답은 클라이언트 수신이 확인될 때까지 제한된 메모리에 보관한다. 근무 역할·구매·칩 등의 기준은 바꾸지 않았다. 요청 크기, 빈도, 큐, 유휴 시간에 상한을 둔다.
- 방 `FAB-A-v20`, 프로토콜 20, 기존 쿠키, ID·닉네임·기록·칩·보유품을 유지한다. 데이터 마이그레이션이나 초기화는 없다.

## 검증 및 배포

- 전체 테스트 **343개** 통과, 정적 빌드와 Wrangler 배포 사전 검사 통과.
- 격리한 실제 로컬 Worker에서 WebSocket 무응답/즉시 오류/접속 후 무응답을 모의했다. 무응답 핸드셰이크 → HTTPS welcome 2.34초, 다음 새로고침은 HTTPS로 바로 95ms. 10회 파괴로 50칩 적립 후 구매 응답을 잃은 상황에서 재전송해도 한 번만 차감됐으며 방진복·잔액·누적 기록이 두 경로의 재접속 후 일치했다. 구매 검증은 로컬에서만 수행했다.
- 운영 버전 `738f78db-4ec3-4ff0-9dfe-42c8aac26a3d`, 빌드 해시 `0ce5f1ac6b3a`. 기존 검증 계정으로 정상 WebSocket welcome 281/360/454ms, HTTPS welcome 84/499/159ms. 늦은 이전 WebSocket과 HTTPS 접속은 현재 연결을 교체하지 못했고, 최종 계정과 지갑 데이터가 배포 전과 일치했다. 운영 검증 중 게임 명령이나 구매는 수행하지 않았다.
- 운영 HTML을 두 번 읽고 인라인 부트스트랩을 실행해 기존 쿠키 유지와 별도 설정 요청 0건을 확인했다. 69개 모듈과 Worker가 동일 빌드와 일치했고 구버전 안내도 유지된다. 실제 iPhone Instagram에서의 체감과 전체 화면 로딩 시간은 아직 확인하지 못했다.

# 유저 안전팀 배정 간격

사용자가 유저 안전팀 차례가 너무 자주 돌아온다고 알려 조정했다.

- 첫 배정 자격: 누적 플레이 60초 → 300초(5분).
- 임무를 마친 뒤 같은 계정의 재배정 대기: 플레이 90초 → 600초(10분).
- 다른 자격 있는 사람에게 넘기는 간격 15초, 동시 유저 안전팀 1명, 서로 다른 대상 3명 포획 조건은 유지한다.
- 최근 담당자는 대기 시간이 끝나기 전에는 혼자 접속해 있어도 다시 배정되지 않는다. NPC 안전팀은 기존대로 순찰한다.
- `activeSeconds`는 기존대로 입장 후 팹 안에 있고 최근 통신한 시간이다. 로그아웃 시간은 포함하지 않으며, 매 접속마다 첫 5분을 새로 세는 방식은 아니다.

기존 저장된 `eligibleAfter`는 이전 임무 완료 플레이 시간 + 90초다. 구버전 기록에는 510초만 더해 동일한 종료 시점부터 10분을 계산한다. `safetyDutyVersion: 2`를 함께 저장하여 재접속/서버 재시작 때 대기를 다시 늘리지 않는다. 이미 10분을 넘게 쉰 계정은 추가 대기가 없다. 진행 중이던 안전팀 역할과 포획 진행은 재접속 시 이어간다.

유지보수: v2로 기록을 저장한 뒤 이전 코드를 운영하면 이전 `profile()`이 버전 필드를 제거할 수 있다. 그런 기록에 v2를 재적용하면 510초가 추가될 가능성이 있으므로 정책을 되돌릴 때도 버전 필드 저장을 유지하고, 실제 코드 롤백이 필요했다면 재배포 전에 이관 기준을 검토한다.

일반/안전팀 닉네임, ID, 파괴/수리, 칩/구매품과 플레이 시간은 초기화하지 않는다. 기존 배정 횟수 우선순위, 수리 중·OHT·보호 구역·앉기/눕기 등의 배정 제외도 유지한다. 클라이언트 이동과 화면에는 변경이 없다.

검증: 전체 385개 테스트와 구문/빌드 검사 통과. 신규 경계 검사 6개에서 첫 배정 300초, 단독 사용자도 종료 후 600초까지 재배정 차단, 구버전 1회 변환과 반복 재접속/재구축, 기존 구매품/칩/닉네임/파괴·수리 보존, 다른 자격 있는 이용자에게 인계를 확인했다. 기존 임무 진행 복구와 보호 구역 등의 제외 검사도 통과했다. 정적 클라이언트 빌드 결과에는 변경이 없다.

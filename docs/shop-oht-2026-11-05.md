# 상점 아이템 탭·모바일 구성·OHT 표시 끊김

## 변경

- 메뉴의 `꾸미기 · 내 옷장`을 **상점 · 옷장**으로 바꾸고 인스타 표시 바로 아래로 올렸다. 상점 진입창의 제목도 같으며 상점/옷장/칭호 구성을 유지한다.
- 머리·안경·가방·방진복·눈 옆에 **아이템** 탭을 추가했다. 패널티 해제 쿠폰 30칩과 닉네임 변경권 1,000칩을 이곳으로 옮겼다. 옷장에서는 보유한 것만 표시하며 쿠폰 사용은 기존 패널티 안내 버튼으로 한다.
- 아이템 탭은 캐릭터 미리보기와 착용 버튼을 숨겨 한 화면에 구매·수량을 보여준다. 의류 탭은 제목·탭·구매 버튼을 고정하고 상품 목록만 스크롤한다. 상품 칸의 높이를 유지해 가격과 이름이 겹치지 않는다.
- OHT 표시 보간 시간이 프레임당 50ms로 제한된 게임 시뮬레이션 시간만 따라가던 문제를 고쳤다. 저속 프레임에서 표본보다 뒤처져 정지/도약하던 것을 실제 경과 시간으로 재생한다. 보행·물리·기존 카메라 코드는 그대로다.
- HTTPS 우회 연결은 응답 간격을 고려해 차량 표시 버퍼를 0.9초로 둔다. WebSocket은 기존 0.3초다. 3초 넘게 끊긴 표시 표본은 복귀 시 최근 표본으로 시작하며, 서버가 알려준 마지막 위치를 넘어 추측해서 움직이지 않는다. 서버 요청 빈도나 저장량을 늘리지 않는다.

## 검증

- 수정 전 10FPS 재현에서 일정한 차량의 화면 속도가 0~4로 튀었다(정상 테스트 속도 2). 수정 후 10/15/30/60FPS에서 일정한 표시 속도를 유지했다.
- 30/60/120FPS의 5Hz 표본, HTTPS 0.6~0.8초 표본 간격, 장기 중단/복귀·정지 위치, FOUP과 차량의 동일 시간축을 검사했다.
- 전체 588개 중 587개 통과, 기존 대용량 옵션 검사 1개 생략. 마지막 연결 방식 반영 후 관련 10개 재검사 통과. 구문·빌드와 기존 실제 상점 핸들러의 11품목 시착/구매/무료 재착용 검사 완료.
- Chrome 390×660 및 320×568에서 아이템 구매 버튼이 화면 안에 들어오며 바깥 스크롤/가로 넘침이 없음을 확인했다. 격리 계정 쿠폰 90→60칩/1장 구매, 보유 필터 및 새로고침 보존을 확인했다. 실제 로컬 HTTPS 연결의 OHT 시점과 0.9초 버퍼를 확인했다.
- 실제 iPhone 체감 프레임/터치 검증은 하지 않았다. 게임 서버·계정 저장 구조·기록·아이템 가격·원래 카메라 입력/회전은 변경하지 않았다.

배포·공개 검증 증거는 `outputs/shop-oht-release/`의 completed/verification/recovery 파일을 확인한다. 완료 실행기는 다시 돌리지 않는다.

# 스토커 소진 후 FOUP 재고 보충

11/4 밤에 사용자가 스토커의 FOUP을 모두 꺼낸 뒤 다시 채워지지 않는다고 알렸다. 기존 구현은 처음에만 기존 세계의 FOUP을 최대 12개씩 넣고 소진 후에는 이용자의 IN 입고에 의존했다. 23:54 KST 읽기에서 STK01은 1개, STK02는 14개였으며 두 스토커가 모두 비어 있는 상태를 직접 관찰한 것은 아니다.

## 변경 동작

- 마지막 OUT FOUP을 손에 들면 빈 스토커에 사용 가능한 기존 재고를 최대 12개 다시 보관한다.
- 이미 비어 있던 스토커도 OUT을 누르면 보충하고 기존 3초 출고 절차를 시작한다.
- 보충은 서버가 확정한다. 마지막 집기와 보충을 한 번에 저장하며 동시 요청으로 출고나 재고가 복제되지 않는다. 재접속만으로 재고를 바꾸지 않는다.
- 완전히 청소되고 기존 12초 재보충 대기가 끝난 FOUP, 파손 장비 위에 남은 재고, 손대지 않은 포트 재고, 그 밖의 유휴 포트 재고 순으로 재사용한다. 새 FOUP ID는 만들지 않는다.
- 사용자가 들고 있거나 날아가거나 바닥에 놓인 FOUP, 청소 전 잔해, 황금 FOUP, 다른 스토커의 물건은 가져오지 않는다. 사용자 20m 안의 포트 재고, 조작 중인 장비의 포트, NPC가 가져가려는 재고도 제외한다.
- 사용 가능한 재고가 12개보다 적으면 그만큼 보충한다. 모두 사용 중이거나 잔해뿐이면 청소/IN 입고 안내를 한다. 청소 전 잔해를 자동으로 없애는 방식은 아니다.

보관·출고·재보충에는 칩을 지급하지 않는다. 기존 던지기/청소 보상, 계정·이름·지갑·구매품·파괴/수리 기록, 카메라·조이스틱, 이벤트 일정 및 보상은 유지한다. 매 프레임 검색하지 않고 마지막 집기 또는 빈 OUT 요청 시에만 기존 FOUP 목록을 확인한다.

## 검증

- 새 회귀 검사 6개: 12회 소진 후 보충, 기존 빈 저장 복원 후 OUT, 동시 출고, 보호할 FOUP 상태, 전체 장비 파손/실제 청소 대기, 저장·재접속·공유 상태, 서버의 근처 사용자/NPC 재고 보호와 무보상 확인.
- 전체 539개 중 538개 통과, 기존 선택적 최대량 분석 검사 1개 생략. 구문 검사·빌드·차이 공백 검사 통과.
- 격리한 로컬 Worker와 실제 WebSocket 두 개로 빈 OUT 보충/동시 출고 직렬화/마지막 집기 후 12개 보충/두 접속자 공유/저장·재접속을 확인했다. FOUP ID 전체 목록과 두 계정 지갑은 유지했다.
- 로컬 검수 경로와 합성 계정은 운영 배포에 포함하지 않는다. 실제 iPhone 검증은 하지 않았다.
- 산출물: `outputs/stocker-refill-release/{live-before,local-verification}.json`, `refill-tests.log`, `full-tests.log`, `check.log`, `build.log`.
